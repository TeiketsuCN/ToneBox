# 任务 01：实现频谱质量分析（fc-analyze）

> 给机器 B 的第一个任务。做完这个，`fc-analyze` 从 stub 变成可用功能，
> GUI 那边就能显示"这个文件真实音质大概是多少"。

---

## 一、目标

实现 `crates/fc-analyze/src/lib.rs` 里的：

```rust
pub fn analyze(path: &Path, info: &MediaInfo) -> anyhow::Result<QualityReport>
```

输入一个音频文件，输出它的**有效带宽**和**推测的源码率档位**，外加置信度和误判说明。

## 二、验收标准

用 `samples/` 里的对照集跑一遍（44 个已知码率的编码 + 14 个真实 ATRAC），

**档位命中率 ≥ 85%**。这是产品成立的线（低于 50% 说明算法方向错了）。

"命中"的口径：
- 有损样本：`estimate` 字符串里包含真实码率数字，或落在相邻一档内（相邻一档算半分）
- 无损样本：`estimate` 里包含"无损"

## 三、参考实现（照抄，别重写）

**`tools/analyze.py` 已经跑通并标定过**，直接移植它的逻辑：

```
find_edge()  —— 最陡斜率法
TABLES       —— 按编码族分开的阈值表
```

### 关键算法：最陡斜率，不是"跌破 -80dB"

```
1. ffmpeg 解码成单声道 f32，**保持原始采样率**（不要重采样，会引入额外带宽损失）
2. 4096 点 Hann 窗、50% 重叠、跨帧平均功率谱
3. 以 1~4kHz 中频段为参考电平，归一化到 dB
4. 对每个频率点，算 ±300Hz 窗口内的斜率（dB/kHz）
5. 取绝对值最大的负斜率点作为截止频率
6. 按编码族查表
```

为什么不用"跌破 -80dB"：ATRAC 在低频通边沿上方还留着 -45dB 的残差噪声，
简单阈值会被噪声骗过去。真实编码器的边沿陡度都在 **40dB/kHz 以上**，母带衰减和噪底要缓得多。

## 四、实测数据（阈值表就按这个排）

同码率下，不同编码族的截止频率差得非常远：

| 编码 | 码率 | 实测截止 |
|---|---|---|
| MP3 | 64k | **11.4 kHz** |
| ATRAC3 | 66k | **15.4 kHz** |
| AAC | 64k | 12.7 kHz |
| Opus | 64k | **20.3 kHz（全带宽）** |

完整曲线见 `docs/样本清单.md` 第三节。**不要用一张表套所有编码器。**

## 五、三个必须处理的特例

### 1. Opus 必须输出"不可判定"

Opus 在 64k 和 96k 下截止频率只差 38Hz（都是 20.3kHz 左右），
因为它用噪声整形保留了全带宽。**截止法对它完全无效。**

`estimate` 返回"不可判定"，置信度 ≤ 0.15，`caveats` 里说明原因。
别硬套表——那会输出一个自信的错误答案，比不输出更糟。

### 2. 源带宽受限时，高档位不可区分

MP3 320k 均值 18.9kHz，192k 均值 18.2kHz——差不到 1kHz。
因为母版本身只有 ~17kHz 带宽，320k 也只是忠实还原这个上限。

这种情况下给**区间**（"192~320"）和低置信度，不要给单一答案。

### 3. 音源本身高频少 = 必然误判

`aa3_sonateno` 是 48kbps 的钢琴曲，实测截止 19kHz（比同码率的 65k 样本还高）。
因为钢琴几乎没有高频内容，编码器不需要砍。

**判断依据**：边沿下方 2kHz 的平均电平如果已经很低（< -25dB），
说明不是编码器切的，而是音源本来就这样 → 降置信度 + 加 caveat。
