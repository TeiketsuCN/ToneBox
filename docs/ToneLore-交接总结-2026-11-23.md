## 2. 现在有什么（功能地图）

### 转换与顾问
- 112 个输出目标：音频 65 + 视频容器 36 + 设备/复古 11
- 格式百科（34 篇长文，中英）、专利/体积/截止频率/重采样/声道代价提示
- 质量提示分级：`[Rule]` / `[Prediction]`
- 场景推荐：Archive / Phone / Car / Voice，主方案 + 备选 + 代价
- 转换后自检：0 字节、真解码前 10 秒、时长；无损可 `--verify-lossless` 逐样本比对 PCM
- 同名策略：Auto rename / Overwrite / Skip
- `.part` 原子输出（ffmpeg 路径）

### 元数据
- `Tags`：title/artist/album_artist/album/track/disc/date/genre/isrc/lyrics/replaygain
- `tag_support(id)`：容器标签/封面能力表；输出栏会提前警告「会丢标签/封面」

### 音乐库
- 扫描、搜索、专辑/风格/艺术家、封面、歌单（自建，持久化）
- 歌词配对：同名 `.lrc`；歌曲行 `LRC` 标记；左侧「歌词」栏
- 右键：跳转到编解码 / 从列表删除（内存级）/ 编辑或创建歌词

### 歌词管理（顶级页）
- 左侧歌曲列表 + 封面缩略图 + 搜索
- 右侧内置 `.lrc` 编辑器：保存 / Ctrl+S、模板、打开文件夹、未保存提示
- 「试听 / 停止」+「插入时间戳」：播放时按 `[mm:ss.xx]` 追加
- 详情页会显示同名 `.lrc`，按播放位置高亮并滚动

### 控制台
- 标题栏 `>_` 图标，独立终端窗口（`Order::Tooltip`，设置打开时也在最上层）
- 日志：`[START] N job(s)` / `[OK] 路径` / `[FAIL] 错误` / 批次结束
- 命令：`help` / `version` / `logs` / `clear`
- 复制 / 清空 / 打开日志；会话日志落盘
- 注意：目前是**任务级日志**，还不是 ffmpeg 实时 stderr，也不是真 shell

### 设置
- 标签：Display / Behavior / Tools / **Storage** / About
- **每个标签一个独立单列页面**（2026-11-23 重构；以前五个标签共用同一整页，Storage 页甚至是死代码）
- About 独立页：版本、GitHub、Issue、微信/支付宝二维码、许可
- Storage 独立页：默认导出位置、控制台日志、缓存清理、临时文件

## 3. 验证到哪一步（重要，别过度承诺）

### 3.1 单源 × 全部 112 个格式

`tools/validate-real-music.ps1`（1 首 FLAC × 112 个目标）：

- 12 个外部编码器格式以前被脚本硬编码跳过，**其实 CLI 早就派发了**
  （`--convert --to atrac3 / xa / brstm / musepack / optimfrog / vadpcm …` 都能跑）。
  已删掉这个 skip，现在 112 个全跑。
- ffmpeg 读不了 `.xa` / `.dsp` / `.idsp` / VADPCM `.aifc` / `.ofr`，直接 ffprobe 会误报失败。
  `tools/verify-output.ps1` 改成用生成它们的工具回读：
  XA 没有解码器 → 查 2336 字节扇区结构；VGAudioCli / vadpcm 解码成 WAV；ofr `--verify`。
- 最近一轮：**112/112 通过**（约 107 个 ffmpeg 直接验，5 个工具回读/结构检查）。

### 3.2 全库 × 属性矩阵

`tools/validate-library.ps1`：

- 26 个真实文件（22 MP3 + 4 FLAC）各截 12 秒，跑 24 个核心格式；
- 另加 5 个派生属性源：96k/24bit、48k 单声道、8k 单声道、5.1、120 秒长文件——跑完整 97 个音频目标；
- 3 个 NCM 只记 `SKIP_DRM`：加密容器按红线不解密，不能当输入；
- 视频容器（14 个需要视频源的）由 `validate-real-music.ps1` 覆盖，全库脚本只跑音频。

最近一轮结果见 `docs/验证-全库属性矩阵-2026-11-23.md`。

验证能说明「能产出、能解码、时长对得上」，**不能**说明音质/画质、所有参数组合都验证过。

## 4. 已知问题 / 别踩

| 问题 | 说明 |
|---|---|
| 外部编码器验证要看工具 | CLI 已派发 12 个外部格式；验证时 `.xa/.dsp/.idsp/.aifc/.ofr` ffmpeg 读不了，靠 `tools/verify-output.ps1` 用生成工具回读（psxavenc 只能编码 → XA 查扇区结构） |
| 视频容器缺 96k / 5.1 兜底 | wmv / swf / ogv 在 96k 或 5.1 源上会失败；音频目标已自动下混成 2.0，视频容器还没按容器加硬约束（mxf/psp/dv/gxf/vcd 已有） |
| 采样率上限没统一 | wma / wmv / ogv / swf 只吃 ≤48k，wsaud 只认固定档（96k 会被写成 38 秒），vadpcm 只收 16-bit；96k 源会失败（有自检报错，不会静默出坏文件） |
| 控制台无实时 stderr | 只在任务开始/结束/失败时写日志 |
| 歌词只认 `.lrc` | 不读内嵌歌词；没有逐句点击跳转/拖动校准 |
| 歌词「从列表删除」不持久 | 重扫会回来 |
| 启动过渡 | 已从 2s+7×200ms 改为 650ms 最短展示；再调要兼顾「不突兀」和「不卡顿」 |
| 构建被 exe 占用 | 先 `Stop-Process ToneLore` |
| 代理 | GitHub 直连不通，必须 `http://127.0.0.1:7890`；推前确认端口在监听 |
| 路径硬编码 | `tools/*.py` 里有本机绝对路径；仓库目录名仍是 `FormatConverter-source-...`，批量替换时别把路径改坏 |

## 5. 下一步优先级（建议）

1. **视频容器的 96k / 5.1 兜底**：wmv / swf / ogv 现在还只会在失败时报错；照 mxf/psp/dv 的写法在 `video_args` 里按容器加 `-ac 2` / `-ar 48000`
2. **采样率上限表**：wma / wmv / ogv / swf ≤48k，wsaud 固定档，vadpcm 16-bit；现在靠自检拦截，应该在参数层就降采样
3. **控制台升级**：worker 边跑边发 stderr、过滤、详细模式
4. **歌词**：嵌入歌词读取、逐句 seek/打轴、失焦保存策略
5. **发布**：2.0.0 之后的改动（控制台/歌词/Storage/设置分栏/PSP/播放修复/5.1 下混）尚未发 release，确认后发下一个版本

## 6. 发版流程（沿用）

1. 关掉 ToneLore；改版本号三处 + `install.ps1`
2. `python tools\i18n_dict.py` 重新生成词典
3. `cargo build --release -p fc-gui` + 测试
4. `tools\package-release.ps1`、`tools\package-extras.ps1`
5. 更新 README 下载表（大小 + SHA256）
6. 提交 → `tag` → 通过代理 push → GitHub release 上传两个 zip
7. 重下载校验 SHA256；启动新版本确认

代理写法：

```powershell
git -c http.proxy=http://127.0.0.1:7890 -c https.proxy=http://127.0.0.1:7890 `
    -c http.version=HTTP/1.1 push github main
```

## 8. 红线

- 不解释 DRM、不联网、不上传用户文件

- 许可：主程序 MIT；随包 ffmpeg 为 LGPL v3；`ofr.exe` 不再分发
- 发版前必须用户确认；不要擅自发版/推送
