## 一、归属表

| 路径 | 归属 | 说明 |
|---|---|---|
| `crates/fc-core/src/format/lossless.rs` | **机器 A** | 无损格式条目 |
| `crates/fc-core/src/format/lossy.rs` | **机器 B** | 有损格式条目 |
| `crates/fc-core/src/format/device.rs` | 双方都不动 | ATRAC 等只读格式 |
| `crates/fc-core/src/format/mod.rs` | 公共 API | 改之前先留言 |
| `crates/fc-core/src/ffmpeg.rs` | **机器 B** | probe / convert（子进程） |
| `crates/fc-analyze/**` | **机器 B** | 频谱分析（当前是 stub） |
| `crates/fc-core/src/identify.rs` | **机器 A** | DRM 指纹识别（新建） |
| `crates/fc-core/src/lib.rs` | **机器 A** | 只由 A 增删 mod 声明 |
| `crates/fc-gui/**` | **本机** | 界面、队列、状态机 |
| `docs/契约.md` | 双方 | 改之前先说一声 |
| `docs/**` `tools/**` | 双方 | 各自新增文件，别改对方的 |

**硬规则：**

1. GUI 侧**不许**在界面代码里写死格式判断（`if codec == "flac"` 这种）。一切格式知识走 `fc_core::format`。
2. 引擎侧**不许**碰任何 UI 概念（颜色、宽度、文案排版）。
3. 新增一个格式 = **只改 `format.rs` 里加一条 `FormatSpec`**，UI 自动出现，不用改一行界面代码。

### 格式表

```rust
pub struct FormatSpec {
    pub id: &'static str,          // "flac"，唯一键
    pub name: &'static str,        // "FLAC"，显示名
    pub ext: &'static str,         // 输出扩展名
    pub kind: Kind,                // Lossless / Lossy / Uncompressed / Container / Encrypted / Unknown
    pub group: Group,              // Lossless / Lossy / Device / ReadOnly（侧栏分组）
    pub patent: Patent,            // Free / Expiring / Active
    pub can_encode: bool,          // ★ false 的不进侧栏，只出现在解释里
    pub primary: bool,             // ★ false 的收进侧栏「更多 ▾」
    pub blurb: &'static str,       // 侧栏点开后的小字，≤3 行
    pub args: &'static [&'static str], // ffmpeg 编码参数
    pub size_ratio: f32,           // 相对 PCM 的体积系数，用于预估
}

pub fn all() -> impl Iterator<Item = &'static FormatSpec>;       // 全部（无损→有损→设备）
pub fn browsable() -> impl Iterator<Item = &'static FormatSpec>; // can_encode 的那些
pub fn split_group(g: Group) -> (Vec<&'static FormatSpec>, Vec<&'static FormatSpec>); // (默认, 更多)
pub fn by_id(id: &str) -> Option<&'static FormatSpec>;
pub fn default_target() -> &'static FormatSpec;
pub fn targets_for(src: Option<&MediaInfo>) -> Vec<Choice>;     // 带警告
pub fn encoder_for(id: &str) -> Option<&'static str>;           // 运行时编码器探测用

// —— 可调参数（2026-11-08 晚新增）——
pub struct ConvertOptions { flac_level, bit_depth, mp3_bitrate, opus_bitrate,
                            vorbis_q, aac_bitrate, ac3_bitrate, eac3_bitrate, wma_bitrate }
pub enum Knob { FlacLevel, BitDepth, Mp3Bitrate, OpusBitrate, VorbisQuality,
                AacBitrate, Ac3Bitrate, Eac3Bitrate, WmaBitrate }
pub fn knobs_for(spec) -> &'static [Knob];          // 这个格式能调什么
pub fn args_for(spec, opts) -> Vec<String>;         // 旋钮 → ffmpeg 参数（唯一入口）
pub fn bitrate_choices(id: &str) -> &'static [u32]; // 码率档位表（kbps），GUI 只照着画按钮
pub fn bitrate_of(spec, opts) -> Option<u32>;       // 当前参数下的目标码率
pub fn knob_note(spec) -> Option<&'static str>;     // 旋钮下面那行小字
pub fn estimate_size(info, spec, opts) -> u64;      // 有固定码率的按码率×时长算
```

**格式知识只放在 core。** 码率档位、`-ar 48000`、体积估算都必须走上面这几个函数；
GUI 里出现 `[128, 192, 256, 320]` 这种数组就算违规。

**`ConvertOptions` 带 `#[serde(default)]`。** 加字段时老 `config.json` 缺字段会补默认值；
不加这行整个设置会解析失败、被 `unwrap_or_default()` 静默重置（踩过一次）。

**`can_encode` 是整个设计的关键开关。**
ATRAC9、WMA Pro、Musepack 这些"能解码但不给编码"的格式靠它自动从侧栏划掉，
只在格式百科里出现、并说明为什么。AAC / AC-3 / E-AC-3 / WMA 已经放开（见
`docs/法律边界-重新评估.md`），但仍要走 `encoder_for()` 探测——二进制里没有该编码器时
界面画横线，提示用户换 ffmpeg 构建。

**侧栏不做折叠。**
所有能编码的格式一次性排开，靠紧凑排布（行高 24px、字号 11.5）让一屏放下。
`primary` 字段保留但目前未使用，留给以后格式数量真的爆炸时再用。

## 三、fc-analyze 契约（已实现，产品实现是 Rust 版）

```rust
pub struct QualityReport {
    pub cutoff_hz: f64,            // 低通边沿，找不到时 = Nyquist
    pub slope_db_per_khz: f64,     // 负值，越负越陡
    pub estimate: String,          // "128" / "无损/CD" / "48/256" / "不可判定"
    pub confidence: f64,           // 0.0 ~ 1.0
    pub caveats: Vec<String>,      // 误判风险，宁可多写
}

pub fn analyze(path: &Path, info: &MediaInfo) -> Result<QualityReport>;
```

`tools/analyze.py` 是**同步的参考实现**，两边阈值必须一致（改了一边就改另一边，
否则 `calibrate.py` 和 `cargo test -p fc-analyze` 会给出两套结论）：

- 用**最陡斜率**找边沿（±300Hz 窗口），不是"跌破 -80dB"
- 阈值表**按编码族分开**：mp3 / aac / atrac3 / atrac3p / vorbis / generic 各一张
- **Opus 输出"不可判定"**——它 64k 也保留全带宽，截止法无效
- **HE-AAC / xHE-AAC 也输出"不可判定"**，靠 ffprobe 的 `stream.profile` 识别
- **ATRAC 结论压保守**：单样本档位只给区间、统一加 caveat、置信度上限 0.60
- 解码时**不要重采样**，保持原始采样率

实测数据见 `docs/样本清单.md`，60 个样本（44 个对照 + 16 个真实 ATRAC）。

## 四、出错时怎么办

- 引擎侧发现契约不够用 → 在本文件加一条提案，等本机确认
- GUI 侧需要新字段 → 同上
- 不要靠"先改了再说"，那是最容易把两台机器的活搅在一起的做法
