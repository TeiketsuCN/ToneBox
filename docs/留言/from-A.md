## 2026-11-08 九轮 · 单人（库封面 + 用户配置）

用户要求：音乐库要能看专辑封面；左侧「库」里文件夹路径是歪的；要有持久化的用户配置，
放左下角，123 套、支持重命名/导出/导入。

### 做了什么

- **库封面**：列表每行加 36px 封面。不在扫描时全抽（几千首会卡死），改成**滚到哪抽哪**：
  行进入视口才排队，后台线程抽图 → 缩到 40×40 → 回主线程建纹理，按路径缓存；
  重扫时清缓存。
- **路径歪**：`paint_clipped` 是从左上角画的，30px 行高里文字贴顶。新增 `paint_clipped_v`
  按 galley 高度取垂直中线，文件夹和单文件的路径都改用它。
- **用户配置**：`settings::Profile` = 转换参数 + 输出位置 + 元数据偏好的一整块快照。
  - 左下角「配置」列表：点行切换（切换前先把当前改动写回），`改` 改名、`+` 新建、右键删除；
  - `导出` 存成 JSON（全部配置 + 当前下标），`导入` 追加进来、重名自动加后缀；
  - `Settings::save()` 会先 `snapshot_active()`，所以"改了参数没保存进配置"不会发生；
  - 默认给 `配置 1/2/3` 三套（老配置第一次加载时用当前设置生成）。

### 三个坑

1. 改名输入框如果预填原名，用户打字会接在后面（实测"配置 2车载配置"）。改成空缓冲 + 原名当 hint。
2. egui 默认字体没有 `✎` `＋` 的字形，直接画成豆腐块——换成 `改` 和 `+`。
3. `save()` 里先 snapshot 再写盘；否则切换配置时会把"当前展开值"和"配置快照"弄反。

### 验证

- 用用户自己的 `D:\FLAC`（39 首）实测：封面一屏一屏加载出来、滚动到哪出到哪；
- 库页路径垂直居中；配置面板切换（active_profile 落盘 = 1）、改名为"车载"成功；
- `cargo test -p fc-core --lib` 34 个全过。

## 2026-11-08 五轮 · 单人（设置页重做）

用户提了三条：

1. 设置里能不能调字体；
2. 设置页不要纯黑，要跟主界面一样；
3. 设置按钮从侧栏挪到图钉旁边。

### 做法

- **入口**：侧栏底部的「设置」按钮删掉，标题栏图钉左边加了一个滑杆图标（`TitleBtn::Settings`，
  用 painter 画三条滑杆）。侧栏因此多出约 30px 给格式列表。
- **背景**：设置页的 `Frame` 从 `tint(BG, 255)`（纯黑）改成 `tint(BG, 148)`，
  并且设置打开时**不画主界面的三栏**——这样玻璃底下只透出壁纸，不会透出队列文字。
- **字体**：加了 `Settings.ui_scale`（90/100/110/120%），用 `ctx.set_zoom_factor()`
  整体缩放。为什么不用 `text_styles`：界面里到处是写死的 `.size(9.5)`，改样式表没用。
- **滚动**：正文包进 `ScrollArea`（标题栏固定在外面），120% 时也能看到「关于/支持开发」。

### 两个真坑

1. `frame.rs` 的 `TITLE_BUTTONS` 写死 4，加了第 5 个按钮后它落在 `HTCAPTION` 区域，
   **点了只会拖窗口**。改按钮数必须同步这个常量（还把右边距 10px 一起算进命中区）。
2. `WM_NCHITTEST` 里的尺寸也得乘 zoom，否则 120% 时按钮边缘点不到。
   现在 `frame::set_ui_scale()` 每帧从 `cfg.ui_scale` 同步过去。

### 第三个坑（做完才发现的）

设置打开后，**标题栏的关闭/最小化/图钉全点不到**——因为 `set_min_size(area.size())`
加上 Frame 边距让 Area 比区域大，egui 把它顶到 y=0，Foreground 层盖住了标题栏。
用 `layer_id_at(pos2(1094,22))` 打印才定位到（返回的是 Foreground 而不是 Background）。
修法：`min_size` 扣掉 Frame 边距。wiki 页同样的写法一起改了。

### 验证

100% / 120% 都实机截图确认：设置页玻璃底、缩放即时生效、正文可滚、返回按钮和 Esc 都正常，

## 2026-11-08 四轮 · 单人（ATRAC AL 识别 + 专利问题）

用户问了三件事：ATRAC Lossless 呢、aptX Lossless 呢、为什么一堆开源工具敢带
Dolby Digital Plus（E-AC-3）。

### 代码：ATRAC Advanced Lossless 现在能认、能解

- `device.rs` 新增 `atrac_al`（`Kind::Lossless`，`can_encode: false`）。
  侧栏 `设备专用` 里会出现一行灰的 "ATRAC AL"，只能读。
- `codec_label()` 认 ffmpeg 的两个名字：`atrac3al` → "ATRAC3 AL"、
  `atrac3plusal` → "ATRAC3+ AL"。
- `fc-analyze` 的 `is_lossless_codec` 把这两个名字也归到无损：
  不然会被 ATRAC3 的码率表硬猜成 "66~105"，那是错的（它解出来是逐比特还原的）。
- wiki 文案写清了：有损核 + 无损残差、几乎只存在于 SonicStage 导出的 .oma/.aa3、
  ffmpeg 只解不编、**本项目没有真实样本，只验证了 codec 名和文案**。

### 为什么不做 ATRAC AL / aptX Lossless 编码

| | 结论 | 原因 |
|---|---|---|
| ATRAC AL | 只读 | ffmpeg 只有解码器，atracdenc 不支持，**没有开源编码器**；文件基本都套 OpenMG |
| aptX Lossless | 不做 | 2021 年 Qualcomm 私有扩展，无公开规范/无开源实现，专利到 2041；而且它是蓝牙链路编码，不是存档格式 |

### 文档：把"开源工具为什么敢带 DD+"写清楚

`docs/法律边界-重新评估.md` 新增一节，核心是五点：专利期（AC-3 2009~2017 到期、
DD+ 20 年期基本走完）、ffmpeg 的实现是 clean-room（著作权干净，只剩专利）、
执法对象是有营收的硬件/软件厂商、跨国诉讼成本、商店审核才是真卡点。
结论仍然是："没被告" ≠ "合法"，是期望损失低；并再一次声明这是工程判断，不是法律意见。

### 验证

`cargo test -p fc-core --lib` = **34 个全过**；新增一个测试锁住
`atrac3al` / `atrac3plusal` 的 label 和 `is_lossy == false`（写反了界面会劝用户
"转无损不会增加信息量"，正好说反）。

## 2026-11-08 三轮 · 单人（ATRAC 外部编码器）

用户要求两件事：**设置里加上 atracdenc（LGPL-2.1+）**，以及**侧栏里 ATRAC 灰着并说明
"系统还没装这个"，装了才能编码**。核心还是"我们不承担分发编码器的风险"。

### 做法

- `crates/fc-core/src/external.rs`：只做两件事——**找**（程序目录 → 程序目录\atracdenc → PATH）
  和**调**（ffmpeg 解码成 44.1k/16bit WAV → atracdenc 编码 → copy 到目标路径）。
- `device.rs` 里 ATRAC1 / ATRAC3 / ATRAC3+ 改 `can_encode: true`，但界面还要过
  `external_encoder()` + 检测：**没装 = 灰 + 横线 + 悬停提示"你系统里还没装 atracdenc"**；
  装了才可选。ATRAC9 保持只读。
- 设置页「关于」新增一行 `ATRAC 编码 | atracdenc（LGPL-2.1+，需自行安装）`，
  下面显示检测状态 + 「重新检测外部工具」，再下面一段说明"不随包、装不装由你决定"。
- `tools/fetch-atracdenc.ps1`：下载并放进 `程序目录\atracdenc\`（不进安装包）。
- 输出列对 ATRAC 显示"由外部编码器 atracdenc 完成（不随包，需你自己安装）"。

### 实测（用官方 Windows 构建 0.2.3，x86）

| 格式 | atracdenc 参数 | 产物（ffprobe） |
|---|---|---|
| ATRAC1 | `-e atrac1 -o .aea` | atrac1 / 44100 / 292000 |
| ATRAC3 LP2 | `-e atrac3 -o .oma` | atrac3 / 44100 / 132300 |
| ATRAC3 LP4 | `-e atrac3_lp4 -o .oma` | atrac3 / 44100 / 66150 |
| ATRAC3+ | `-e atrac3plus -o .oma` | atrac3p / 44100 / 352800 |

界面实跑：FLAC → ATRAC3 132k，产物 496224 字节，ffprobe 与上表一致；
ATRAC3+ 也能选（352k 固定）。没装时侧栏三条画横线，悬停就是"还没装"的提示。

### 踩到的坑（都写进 `docs/待办-UI改造.md` 了）

1. `-e` 名字和文档不一致：`-h` 写 `atrac3_lp`，实际只认 `atrac3_lp4`；man page 又写成 `atrac3_lp4`。
2. `--bitrate` 只对 RealMedia 生效，对 `.oma` 静默忽略；ATRAC3+ 只有 352k 一档。
3. atracdenc 是 32 位程序，非 ASCII 路径有风险 → 全程用 `%TEMP%` 的 ASCII 临时名。
4. GitHub 直连 504 / API 限流 → fetch 脚本三层兜底，失败就打印手动步骤。

### 对外说法

> 装了 atracdenc 才能转 ATRAC，没装只能解码；编码器不随本程序分发。
> 转出来的 `.oma` 没有 OpenMG 包装，塞不回 Hi-MD——要灌 MD 只能用原厂工具或硬件回录。

## 2026-11-08 二轮 · 单人

用户提了两件事：**高码率转低码率要提醒"会丢细节"、无损转有损也要提醒**；
另外想把采样率也做成可选档位。

### ① 质量风险提示（`quality_warnings`，判断在 core）

详情面板现在按方向出卡片，四条规则：

| 方向 | 卡片标题 |
|---|---|
| 有损 → 无损/未压缩 | 不会增加任何信息量（原有文案，搬进 core） |
| 无损/未压缩 → 有损 | **会丢掉一部分细节**（带目标码率） |
| 有损 → 有损，目标码率低 8k 以上 | **目标码率比源文件低**（带源/目标两个数字） |
| 有损 → 有损，目标码率高 20% 以上 | **码率调高也不会变好**（丢掉的高频不会回来） |
| 手选采样率 > 源采样率 | **升采样不会增加信息**（体积变大、内容不变） |

文案刻意只陈述事实（"会永久丢掉一部分信息""二次编码还会再掉一点"），
不吹"能听出来差多少"——我们没有 ABX 数据。

### ② 采样率档位（`rate_choices` / `output_rate`）

- 无损族：44.1 / 48 / 96 / 192k；MP3·MP2：32 / 44.1 / 48k；AAC·Vorbis：44.1 / 48 / 96k；
  Dolby·WMA：44.1 / 48k
- 默认「自动」= 不传 `-ar`，跟源走（Dolby 例外，按规范 48k）
- 全局选了 96k 再切到 MP3 会自动吸附到 48k，界面高亮"实际会输出的值"
- **Opus 没有这个旋钮**：实测 `libopus` 无论传什么 `-ar`，输出流都是 48k
- 体积估算跟着采样率走：44.1k→96k 的 FLAC 估计从 3.4MB 变 6.8MB

|---|---|
| `cargo test -p fc-core --lib` | **31 个全过**（新增：采样率进参数、非法采样率吸附、估算跟采样率、质量提示四种方向、老配置 sample_rate = None） |
