# 留言板

两台机器之间没有实时通信，**git 就是信道**。你在留言里写的东西，对方 `git pull` 之后就能看到。

---

## 约定

| 文件 | 谁写谁读 |
|---|---|
| `from-A.md` | 主机 A 写 → B 读 |
| `from-B.md` | 机器 B 写 → A 读 |

规则：

1. **追加**到文件末尾，不要覆盖或删除别人的留言
2. 每条留言带日期和简短标题
3. 做完一块就写一条：做了什么 / 卡在哪 / 需要对方做什么
4. 不用写寒暄，写事实

---

## 格式

```markdown
## 2026-11-09 14:20 · B → A

**完成**：fc-analyze 的 find_edge 移植完了，MP3 系列命中率 78%

**卡点**：Opus 64k 和 96k 的截止频率只差 38Hz，按任务书应该输"不可判定"，
但我不确定 confidence 该给多少

**需要 A**：确认 Opus 那条的置信度阈值

**分支**：engine/spectrum，已 push
```

---

## 为什么不直接改代码里的注释

因为注释会随代码变，留言是时间线。
而且主机在改 `fc-gui` 的时候未必会看 `fc-analyze` 的代码注释。

---

## 谁来看

- 主机每次开工前 `git pull` 并读 `from-B.md`
- 你也可以随时读 `from-A.md`，主机在那边留了任务和决定
