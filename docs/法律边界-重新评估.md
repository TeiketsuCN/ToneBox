# 版权与法律边界 —— 重新评估

> 2026-11-08。起因：拿到真实样本后发现 `.oma` 绝大多数是加密的，简报第七节的"干净栈"结论过于乐观，需要重写。
> 本文不是法律意见。商业发布前必须找律师做一次 FTO（自由实施）检查。

---

## 一、先把四层风险拆开

| 层 | 谁承担 | 风险 | 说明 |
|---|---|---|---|
| **1. 你的代码** | 你 | 极低 | 写一个"调用 ffmpeg 的转换器"本身不侵权。HandBrake / XLD / fre:ac / Shutter Encoder 都这么干，活了十几年 |
| **2. 用户的行为** | 用户 | 低 | 用户转自己买的碟，多数辖区属私人复制/格式转换。中国《著作权法》第24条合理使用；日本第30条私的複製 |
| **3. DRM 规避** | **你 + 用户** | **极高，可能刑事** | 这是唯一的真雷区，见下 |
| **4. 编解码专利** | 你（若内置） | 中，可规避 | 取决于内置哪个编解码器 |

**关键认知：合理使用是用户行为的抗辩，不是软件作者的免责。**
简报里写的"格式转换属合理使用"是错位的——那句话保护用户，不保护你。

---

## 二、真正的雷区，按危险度排序

### 1. 解密 Sony OpenMG / MagicGate（绝对红线）

- **中国**：《著作权法》第49条禁止规避技术措施，第53条定责任。**第49条没有"私人使用"例外**——即使自己听，破解也违法。
- **美国**：DMCA §1201 反规避，§1204 有刑事条款。
- **日本**：2018 年修法后对技术保护手段规避的规制加重（第120条の2）。
- **现实后果**：刑事风险之外，更致命的是 **GitHub DMCA 下架 + 微软商店/苹果商店拒审 + 支付通道封禁**。产品直接死。

**结论：不碰。** 与简报一致，但要说清"为什么"：不是道德洁癖，是分发渠道会直接封杀。

### 2. 打包 GPL 构建的 ffmpeg

- 子进程调用（用户自己装的 ffmpeg）= 独立程序，不传染 ✅
- 安装包里塞一个 gyan.dev 的 `ffmpeg.exe`（GPL 构建）= 你成了 GPL 软件的分发者，必须随附完整源码、GPL 文本、不附加额外限制
- 更稳的做法：**不打包**，首次启动引导用户自己下载，或检测系统已有 ffmpeg

### 3. 编解码器专利（能用，但要看是哪个）

| 编码 | 专利状态 | 商用 |
|---|---|---|
| FLAC / Opus / Vorbis / PCM | 无 | ✅ |
| MP3 | 2017 全部到期 | ✅ |
| ATRAC3 | 1999~2001 申请，20 年期已满 | ✅ 大概率安全 |
| ATRAC3plus | 2003~2004 申请 | 🟡 2023~2024 前后到期，边缘 |
| **ATRAC Advanced Lossless** | 2006 前后申请 | 🟡 2026 前后到期；反正没有开源编码器 |
| **ATRAC9** | 2013~2014 申请 | ❌ **2033 前后才到期，仍在保护期** |
| **aptX Lossless** | 2021 前后申请 | ❌ **2041 前后才到期；没有公开规范/开源实现** |
| AAC-LC | 基础专利多已到期 | 🟡 但 Via LA 仍按池收费，别主动碰编码器 |
| AC-3 | 1992 年的标准，核心专利 2009~2017 陆续到期 | ✅ 已开放（见下文"立场调整"） |
| E-AC-3（Dolby Digital Plus） | 2004 年前后，20 年期基本走完，可能有零散后期专利 | 🟡 已开放（跟随行业惯例，见下文） |
| H.264 / H.265 / AC-4 | 需授权 / 活跃专利池 | ⚠️ 别碰 |

注意：**解码**和**编码**的专利风险不一样。用户自带 ffmpeg 去解码 ATRAC9，风险在使用者；你内置 ATRAC9 解码并商业售卖，风险在你。

### 4. 商标

- ❌ 产品名叫 "ATRAC Converter"、"Sony MiniDisc 救星"（Sony 商标）
- ✅ "支持 ATRAC 格式的转换工具"（描述性使用）
- 同理：Dolby、DTS 只能描述性提及

## 三、对产品设计的直接冲击（比法律问题更严重）

**我们拿到的 6 个 `.oma` 全都能解码——因为它们是无 DRM 的测试样本。**

真实世界的 `.oma` 是 SonicStage 写出来的，套着 OpenMG 加密，`ffmpeg` 会直接报"no audio stream"。

也就是说：

> v0.1 "`.oma` → FLAC" 这条主线，**覆盖不了绝大多数目标用户**。
> MiniDisc 玩家手里的文件，八成打不开。

这是产品层面的硬事实，必须现在决定怎么办。三个选项：

**A. 只做 DRM-free 的一小撮**（PSP `.at3`、无 DRM 的 `.aa3`、老 `.oma`）
→ 诚实但市场小，可能只覆盖 10~20% 的文件

**B. 做"检测 + 告知 + 替代路径"**
→ 打开文件时识别出 OpenMG 加密，明确告诉用户"这个文件有 DRM，法律上我们不能解，官方工具已停服"，
   然后给出合规出路：光纤/USB 声卡从硬件回录（MD 机数字输出 → 声卡 → 无损录音）
→ 这一段"解释"恰好是简报里说的产品价值所在，而且完全无风险

**C. 转做硬件回录伴侣工具**
→ 检测 MD 播放器的数字输出、自动分轨（靠曲目间隙检测）、自动命名、质量评估
→ 完全绕开 DRM，而且是真需求——老 MD 玩家现在就是这么干的，只是全靠手工

**推荐 B + C 的组合**：不承诺"解密"，承诺"从硬件把声音完整录出来，并告诉你录到的是什么质量"。

---

## 四、成本可控的合规动作

1. 不打包 ffmpeg；不内置任何 GPL 代码
2. 不做 DRM 解密；README 明写"不支持加密文件及原因"
3. 输出格式只用 FLAC / WAV / Opus（零专利）
4. 不提供云端转换服务（服务端复制 = 直接侵权，且要处理用户上传的音乐）
5. 不做"批量下载/扒取"类功能
6. 产品名避开 ATRAC / Sony / Dolby
7. `cargo-deny` 卡死 GPL/AGPL 依赖
8. 真要商业化：一次 FTO 律师咨询（约 ¥1~3 万），比事后应诉便宜三个数量级

---

## 五、一句话

**写转换器不犯法，破解 DRM 犯法，内置专利未过期的编码器会被索赔。**
把"破解"从产品里彻底删掉，改用"检测 + 解释 + 硬件回录"，风险归零，而且卖点更硬。

## 2026-11-08 · 立场调整：随包 ffmpeg + 开放 AAC

用户要求"做到 Shutter Encoder 那种程度"，并说明会放捐赠收款码。下面是调整后的判断。

### 为什么之前是保守的

早先的做法是：**不打包 ffmpeg**（只调用用户自己装的），**不开放 AAC**（`can_encode: false`）。
理由是"专利期内不碰"。

**这个判断过度保守了。** 真实的行业惯例是：

| 项目 | 打包 ffmpeg | 提供 AAC 编码 | 收费 |
|---|---|---|---|
| Shutter Encoder | ✅ | ✅ | 免费/捐赠 |
| HandBrake | ✅ | ✅ | 免费 |
| Shotcut | ✅ | ✅ | 免费 |
| VLC | ✅ | ✅ | 免费 |

这些项目做了十几年，没有因为编码器专利被起诉。原因：

1. **没有营收或营收极低**——告赢了也拿不到钱
2. **专利池告的是卖授权的公司**（MainConcept、Telestream、Apple）
3. **ffmpeg 遍地都是**，要告告不完

"没被告"不等于"合法"，但它是行业实际运行的方式。我们现在的选择是：**跟随行业惯例，不假装比整个行业更干净**。

### 现在的做法

**打包**：`tools/fetch-ffmpeg.ps1` 下载 BtbN 的 **LGPL 共享构建**到 `vendor/ffmpeg/`，
安装时拷进 `D:\Apps\FormatConverter\ffmpeg\`。

- **不用 GPL 构建**：gyan.dev 的 full build 带 `--enable-gpl`（x264/x265），
  随包分发会触发 GPLv3 义务；我们只做音频，用不到那些组件。
- **LGPL 共享版**：exe + dll 共 152 MB，静态版要 400 MB 以上。
- 随包附 `LICENSE-ffmpeg.txt`，满足 LGPL 的许可证保留要求。
- 动态链接、独立进程调用 → 我们的 MIT 代码不受传染。

**开放 AAC**：`can_encode: true`，码率 128/192/256/320 可选。

### 仍然不碰的

- **DRM 解密**——这条线不动，`.ncm` / `.mflac` / OpenMG 仍然只识别、只解释
- **批量下载**——不做

### 捐赠的影响

放收款码会让项目从"零营收"变成"有少量收入"，理论上扩大了一点点被追的暴露面。
但：

1. 捐赠不是销售，没有对价关系
2. 量级远达不到专利池的起诉门槛
3. 开源 + 公开代码 + 可审计，反而比闭源商业软件更容易说明"善意使用"

**这不是法律意见，是工程判断。真要商业化（收费、公司主体、上架应用商店），
必须重新评估，那时候风险性质会变。**

## 2026-11-08 · 第三轮：开放 ATRAC 输出，但走外部工具

用户问："只是把一首无 DRM 的歌转成 ATRAC，有那么严重吗？"

答案是分层的：**个人自用不严重，分发编码器才是风险点。** 所以这次的做法是
把两件事切开：

### 我们做了什么

- 侧栏的 `设备专用` 组里，ATRAC1 / ATRAC3 / ATRAC3+ 现在可以作为输出目标。
- 但**编码由用户自己安装的 [atracdenc](https://github.com/dcherednik/atracdenc)（LGPL-2.1+）完成**，
  我们不打包、不进安装包、不写它的代码。
- 装没装由程序检测（`crates/fc-core/src/external.rs`）：没装就是灰的 + 一行说明，
  装了才可选。
- 装法：`tools/fetch-atracdenc.ps1`（下载到程序目录，和 ffmpeg 那种"随包"不是一回事），
  或者手动把 `atracdenc.exe` 放进 `程序目录\atracdenc\`。

### 为什么这样分

| 层 | 谁承担 | 这一轮的处理 |
|---|---|---|
| 歌的版权 | 用户 | 用户自己的无 DRM 文件；自用转换属私人复制，不碰传播 |
| DRM | 我们 + 用户 | **仍然零容忍**：OpenMG / NCM / QMC 只识别、不解密 |
| 编码器专利 | 谁分发谁担 | 我们不触发：包是空的，程序只调用用户装的二进制 |

atracdenc 是**逆向实现**：ATRAC1 专利早过期，ATRAC3 20 年期已满，
ATRAC3+ 2023~2024 前后到期（边缘）。ATRAC9（2013~2014 申请，2033 左右到期）
**不开放**——atracdenc 也不支持它。

### 没改的边界

- **ATRAC9 仍然只读**：专利在保护期。
- **不做 OpenMG 包装**：所以"转出来的 .oma 能不能直接塞回 Hi-MD"我们不承诺；
  真要灌 MD，仍然只能走索尼原厂工具或硬件回录。
- 产品名、宣传语里不出现 "Sony / ATRAC Converter" 这类商标性用法。

### 对"对外口径"的影响

不能再说"本工具支持 ATRAC 编码"——准确说法是：

> **装了 atracdenc 才能转 ATRAC；没装就只能解码。编码器不随本程序分发。**

这句话也直接写在设置页和侧栏的灰色提示里。

### 为什么 E-AC-3 这类"有人在收专利费"的编码器，开源工具都敢带？

用户问过一个很实际的问题：*一堆开源工具都带 Dolby Digital Plus，他们真不怕被告？*

拆开看，真实原因不是"没人管"，而是**风险被集中在别的地方**：

| 原因 | 说明 |
|---|---|
| 专利期 | AC-3 核心专利 2009~2017 到期；E-AC-3 2004 年前后，20 年期基本走完。真正活跃的是 AC-4 / Atmos 这一代 |
| 实现来源 | ffmpeg 的 ac3/eac3 编码器是社区自己写的（clean-room），**不含 Dolby 代码**，著作权上干净；剩下的只有专利问题 |
| 执法对象 | 专利池（Via LA / Dolby）告的是有营收的硬件/软件厂商（电视、功放、转码服务）；告 HandBrake 拿不到钱，还挨舆论 |
| 成本 | 跨国专利诉讼百万级；被告得有钱。免费项目是"低回报目标" |
| 商店门槛才是真卡点 | 微软商店/苹果审核会问编解码授权；SoX、VLC 上架被卡的历史就在那 |

**"没被告"不等于"合法"**，只是期望损失低。我们的做法是跟随行业惯例，并且把话说清楚：
这是工程判断，不是法律意见；一旦收费/上架应用商店，性质就变了（见文末）。

### ATRAC Advanced Lossless 和 aptX Lossless 为什么不做编码

- **ATRAC AL**：ffmpeg 只有解码器（`atrac3al` / `atrac3plusal`），atracdenc 也不支持；
  专利 2006 年前后申请、这几年到期，但**没有开源编码实现**。所以本项目只把它当只读格式：
  能认、能解、能转出去，不能转进来。
- **aptX Lossless**：2021 年的 Qualcomm 私有扩展，**没有公开规范、没有开源实现**，
  专利 2041 前后才到期；而且它本质是**蓝牙链路编码**，不是存档格式——
  ffmpeg 能编的只是老的 aptX / aptX HD 原始帧，存成文件没有任何播放器/设备会认。
  结论：不做，也不值得做。
