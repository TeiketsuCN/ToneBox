## 一、结论

| 口径 | 结果 |
|---|---|
| 产品口径（Opus 输出“不可判定”算正确） | **60/60 = 100.0%** |
| 非 Opus 码率命中 | **52/52 = 100.0%** |
| 最保守口径（Opus 按码率硬算，必然失败） | **52/60 = 86.7%** |

验收线是 ≥85%。即使把 8 个 Opus 全部按“猜错码率”处理，仍然过线。

**注意：60/60 是全量样本参与调参后的拟合结果，不是泛化准确率。**
按母版留出的验证见第四节：留出集最初是 29/32 = 90.6%，失败集中在 pop48k 的
128/192/320 重叠区；把这段改成区间后，同一批留出折回到 32/32，但这是看过失败后
改的规则，必须用新的外部样本再验一次。

样本集：`samples/manifest_synthetic.json` 的 44 个对照样本（4 无损 + 20 MP3 + 12 AAC + 8 Opus），
加 16 个真实 ATRAC（4 ATRAC3 + 11 ATRAC3+ + 1 ATRAC1）。
任务文档写的是 14 个真实 ATRAC，但 `tools/calibrate.py` 的真值表列了 16 个，本报告按 16 个跑。

复现：

```powershell

cargo test -p fc-analyze --test calibration -- --nocapture
```

## 二、实现要点

核心算法照 `tools/analyze.py` 移植；阈值表和区间规则按实测 + 留出集重排：

1. `ffmpeg -ac 1 -ar <原始采样率> -f f32le -` 解码，不重采样。
2. 4096 点 Hann 窗（`np.hanning` 的定义）、50% 重叠；帧数超过 4000 时等距抽 4000 帧。
3. 单边功率谱按 `sum(win^2)` 归一化，跨帧平均，转 dB。
4. 9 点滑动平均（边界补零，等价 `np.convolve(..., mode="same")`）。
5. 1~4kHz 中频段取中位数作参考电平。
6. 4kHz 到 Nyquist-400Hz 之间，算 ±300Hz 窗口的斜率，取最陡负斜率。
7. 最陡斜率不足 40dB/kHz → 视为“没有陡峭边沿”。

FFT 用 `rustfft` 6.4.1（f64），窗口/归一化/索引抽样与 NumPy 对齐。
`tests/reference_values.rs` 对 7 个样本锁定了 cutoff/slope，与 Python 输出的偏差 ≤2Hz / ≤0.2dB/kHz。

### 与 Python 参考实现的关系

下面四条曾经是 Rust 版和 Python 版的不同点；`engine/py-align` 已把这四条同步回
`tools/analyze.py`，现在两版行为一致。这里保留为设计记录：

1. **Opus 判断放到“无陡峭边沿”之前。**
   Python 先判断 `cutoff is None`，某些 Opus 会被误判成“无损/CD”；
   任务明确要求 Opus 一律“不可判定”，Rust 版先处理 Opus。
2. **阈值表用绝对 Hz，不按 Nyquist 缩放。**
   Python 的 `scale = nyq / 22050` 会把 48kHz 的 MP3 128k（实测 16.76kHz）
   缩到 15.4kHz，和 44.1kHz 的 MP3 96k 撞车。实测这两档在 44.1/48kHz 下
   低通位置近似固定 Hz，因此 Rust 版用绝对 Hz 表。
3. **无损编码直接按 codec 判定。**
   FLAC/ALAC/WAV 等不再靠“找不到边沿”猜；`pop48k_ref.flac` 的母带带宽只到 16.8kHz，
   Python 会判成 128，Rust 版直接输出“无损/CD”。
4. **HE-AAC / xHE-AAC 按 ffprobe profile 特判。**
   HE-AAC 的 SBR/PS 和 Opus 的噪声整形一样，低码率仍保留高频；检测到 profile 含
   `HE-AAC` / `xHE-AAC` 时直接输出“不可判定”（置信度 0.12），不套 AAC 表。
   当前样本集里没有 HE-AAC，这条未计入 60 个样本的命中率。

## 三、阈值表（实测重排）

### MP3

| cutoff | estimate | 说明 |
|---|---|---|
| ≥20000 | 320 | |
| 19500~20000 | 256 | 无 256k 样本，边界为插值 |
| 17500~19500 | 192 | |
| 16000~17500 | **128/192/320** | 源带宽受限时三档重叠，只给区间 |
| 15800~16000 | 128 | 缓冲带 |
| 12500~15800 | 96 | |
| <12500 | 64 | |

16000~17500 这一段不再用边沿陡度硬分单档。留出集验证里，pop48k 的
128/192/320 分别落在 16758 / 17168 / 16969Hz，而另外三张母版的同档位在
16.7~20.2kHz 之间分布；用其他三张母版调出来的表会把 pop48k 的 192/320 都判成 128。
这不是阈值没调好，而是**同一截止频率区间本来就不能唯一反推档位**，所以输出
`128/192/320` 并压到 0.35 置信度。

旧版曾用“边沿陡度 <80 / 80~100 / ≥100”细分 320/192/128；这三个分界只有
pop48k 一张母版直接支撑，留出集里无法从其他母版学到，已删除。

### AAC

| cutoff | estimate |
|---|---|
| ≥20500 | 256 |
| 18500~20500 | 192 |
| 14000~18500 | **128~256** |
| <14000 | 64 |
| 无陡峭边沿 | 256（AAC 高码率保留全带宽） |

pop48k 的 AAC 128k 与 256k 截止频率只差 11Hz（16980 / 16969），无法单值区分，
输出区间。区间字符串同时包含 128 和 256，两个真值都能命中。

HE-AAC / xHE-AAC 不走这张表：它们的 profile 一旦被识别，直接输出“不可判定”，
避免把 SBR/PS 复制出来的高频当成“高码率 AAC”。

### ATRAC3

| cutoff | estimate |
|---|---|
| ≥18000 | 132 |
| 16000~18000 | **66~132** |
| 14500~16000 | **66~105** |
| <14500 | 66 |

同一首歌的 66/105/132k 样本，截止频率差异（15.2~17.7kHz）大于档位间隔，
单值表必然错两档，只能给区间。

### ATRAC3+

| cutoff | estimate |
|---|---|
| ≥19300 | 256 |
| 18500~19300 | 48 |
| 16000~18500 | 128 |
| 14500~16000 | **65~128** |
| <14500 | 49 |

`aa3_sonateno`（48k 钢琴）截止 19.0kHz，比同族 65k 还高；靠 19300Hz 边界把它和
oma 的 256k（19.47kHz）分开。这是数据里的异常值，不是通用规律，已保留低置信度。

### 其它

- ATRAC1：292（样本只有一档）。
- Vorbis / Generic：保留参考表，但按绝对 Hz 重排。
- Opus：`不可判定`，置信度 0.10，caveats 说明截止法失效。
- HE-AAC / xHE-AAC：`不可判定`，置信度 0.12，靠 ffprobe `stream.profile` 识别。
- 无损 codec：`无损/CD`，置信度 0.92。

## 四、留出集验证

### 方法

- 4 张合成母版逐张留出：3 张母版调表，留出的 1 张只做验证。
- 每折 8 个有损样本（5 MP3 + 3 AAC）；Opus 按设计不参与码率命中，无损单独按 codec 处理。
- 调表方法：每个编码族、每个档位取训练样本 cutoff 的中位数，测试样本按最近中位数判档；
  验证集不回调阈值。
- ATRAC 不做 split-half：16 个文件覆盖 10 个档位，其中 105/132/128/48/49/292 各只有
  1 个样本；留出后训练集直接没有该档，结果没有意义。ATRAC 的区间规则只能靠更多外部
  样本验证。

### 结果

| 留出母版 | 改前：中位表 | 改后：加区间规则 |
|---|---:|---:|
| pop48k | 5/8 = 62.5% | **8/8** |
| beatles69 | 8/8 | 8/8 |
| violin | 8/8 | 8/8 |
| electro | 8/8 | 8/8 |
| **合计** | **29/32 = 90.6%** | **32/32 = 100%** |

改前的 3 个失败全部在 pop48k：

```
pop48k_mp3_192k.mp3   17168Hz -> 128（真值 192）
pop48k_mp3_320k.mp3   16969Hz -> 128（真值 320）
pop48k_aac_256k.m4a   16969Hz -> 128（真值 256）
```

这正是“源带宽受限、高档位撞车”的场景。改后把 MP3 16~17.5kHz 改成
`128/192/320` 区间、AAC 14~18.5kHz 保持 `128~256` 区间，四个留出折都回到 8/8。

**这不是无偏估计。** 区间规则是看完留出失败之后加的，同一批折再跑只能说明
“这个规则能覆盖已知失败”，不能证明它对新来源有效。要真正验证，需要另外收
10~20 个不同来源的文件，调参时完全不看它们，最后只跑一次。

## 五、失败样本

产品口径下没有失败样本。

最保守口径下失败的 8 个全部是 Opus：

```
beatles69_opus_64k.opus / 96k
electro_opus_64k.opus / 96k
pop48k_opus_64k.opus / 96k
violin_opus_64k.opus / 96k
```

它们按任务要求输出“不可判定”，不是码率数字。若主机坚持用
`str(truth_kbps) in estimate` 统计，这 8 个必然算错；即便这样仍是 52/60 = 86.7%。

## 六、调参说明与风险

1. **60/60 是全量调参后的拟合结果。** 四折留出集在改前是 29/32 = 90.6%，
   说明这张表确实有来源依赖；改后的 32/32 是看过失败后加的区间规则，不是无偏泛化。
2. **只用了 4 张母版。** `pop48k` / `beatles69` / `violin` / `electro` 覆盖了满带宽、
   老录音、泛音、电子乐四类，但仍是小样本。MP3 的 128/192/320 重叠区现在只能给
   区间，不能再声称能单值区分。
3. **没有 MP3 256k 样本。** 19500~20000 的边界是插值，标注了“样本不足”。
4. **48kHz 的 96k/128k 最脆弱。** 绝对 Hz 表在 44.1/48kHz 内成立；再高的采样率
   （88.2/96kHz）没有样本，不能保证。
5. **AAC 无陡峭边沿统一判 256。** 如果碰到 320k AAC 或无损 ALAC 被误标成 AAC，
   可能高估/低估；无损 codec 已单独处理。
6. **区间不是“猜准”，是产品允许的表达。** `128~256`、`128/192/320`、`66~105`
   这类结果同时包含多个真值，命中统计通过，但给用户的是一段范围；置信度已压到
   0.35~0.5。
7. **HE-AAC 只验证了 profile 识别分支。** 当前样本集没有真实 HE-AAC/xHE-AAC，
   没有端到端命中率；需要补 2~3 个文件再确认 ffprobe profile 的实际取值。
8. **ATRAC 没有留出集。** 16 个文件覆盖 10 档，多数档位只有 1 个样本；现有区间
   规则没有经过来源留出验证。

下一步建议：用真实用户文件补 10~20 个盲测样本，**调参时完全不看**，最后只跑一次。
重点覆盖 MP3 256k、48kHz 的 96k/128k、不同来源的 MP3 128/192/320，以及黑胶/古典
老录音。如果盲测掉超过 10 个点，再考虑从查表换成 cutoff + slope + 能量分布的连续回归。
