# 主机芯片音乐格式：NSF / SPC / GBS / VGM / PSF

> 结论先说：这些**不是音频文件，是「音乐程序」**。ToneBox 不把它们做成输出格式，
> 因为从一段 WAV 里「转」出 NSF/SPC/PSF 在原理上不成立——那需要重新作曲和配器，
> 不是格式转换。**但 1.5 起它们可以当输入**：随包 ffmpeg 用 libgme 渲染成 PCM 再转。

---

## 1. 它们到底是什么

| 格式 | 平台 | 里面装的是 |
|---|---|---|
| **NSF** | NES / FC | 6502 机器码 + 音乐数据，靠 NES 的 2A03 声音芯片现场演奏 |
| **SPC** | SNES / SFC | 64 KB 音频 RAM 快照（采样 + 驱动代码）+ 寄存器状态 |
| **GBS** | Game Boy | Z80 机器码 + 4 通道波形/噪声数据 |
| **VGM** | 多平台 | 一颗或多颗声音芯片的**寄存器写入日志**（谁在什么时刻写了哪个寄存器） |
| **PSF / PSF2 / USF / 2SF / GSF** | PS1 / PS2 / N64 / NDS / GBA | 主机音乐驱动 + 采样库，靠模拟 CPU/SPU 播放 |
| **SID** | C64 | 6581/8580 芯片的演奏程序 |
| **HES / KSS / AY** | PC Engine / MSX / ZX | 同类：芯片指令 + 数据，不是 PCM |

共同点：**播放时才产生声音**。同一个文件在不同模拟器/不同芯片模型下听感都可能不同，
它没有「采样率 / 位深」这种波形参数，所以没法像 FLAC→MP3 那样做转码。

## 2. 为什么不能作为输出

1. **信息形态不对**：输出需要「音符、乐器、包络、芯片寄存器序列」，而 WAV 里只有波形。
   从波形反推出乐谱叫**自动转谱（AMT）**，是研究课题，不是转换器该干的事。
2. **需要作曲决策**：就算反推出音高，还得决定用哪个声道、什么包络、哪些采样——
   这已经是编曲，不是格式转换。
3. **版权与 ROM 问题**：NSF/SPC 常包含原厂音乐驱动甚至采样，来源和授权都复杂。

所以 ToneBox 的选择是：**不假装能生成**，在文档里讲清楚；真要「生成」，
去用专门的音乐工具（见第 4 节）。

## 3. 想「听」这些格式怎么办

主机音乐可以**渲染成 WAV**，再交给 ToneBox 转成 FLAC/MP3/Opus：

- **libgme（Game Music Emu，LGPL）**：支持 NSF / SPC / GBS / VGM / PSF / PSF2 / SID / HES / KSS / AY / GYM，
  自带「渲染 N 秒到 WAV」的能力，做命令行小工具很直接。
  **ToneBox 1.5 起已经接了这条链**：随包 ffmpeg 用 `--enable-libgme` 重建，
  `.nsf/.spc/.gbs/.vgm/.psf` 等可以直接拖进程序，转成任意输出格式。
- **vgmstream（开源）**：偏「流式音频」侧，支持 PSF、PS2 的 ADS/VAG、Wii/3DS 的 BRSTM/BCSTM 等，
  解码到 WAV 很成熟。ToneBox 还没接它。
- 现成播放器：foobar2000 + foo_input_vgm/foo_psf、Winamp 插件、各模拟器自带的录音功能。

**为什么默认只渲染 3 分钟**：NSF/SPC 没有「曲目长度」字段，libgme 会一直循环渲染
（实测一个 749 字节的 test.nsf 能渲出 3.4 小时）。ToneBox 统一截前 180 秒，
宁可短一点，也不产出一个几小时的 FLAC。需要更长就自己用播放器录音。

## 4. 想「生成」这些格式怎么办

那要用**音乐制作工具**，不是转换器：

- **FamiStudio**：画谱 + 导出 NSF / 音频
- **Furnace**：多芯片 tracker，支持 VGM / NSF / SPC 等导出
- **ppmck / MuseScore+插件**：MML → NSF
- **OpenMPT**：MOD/XM/IT/S3M 这类 tracker 模块（也不是波形转出来的）
- **PSF 制作**：需要原厂工具链/驱动，基本只存在于同人改版和 rip 流程里

这些工具的共同点是：**你写的是音乐，它生成的是芯片程序**。ToneBox 不会替代它们。

## 5. 那到底有哪些「主机音频」能真正加进 ToneBox

已经有的和可以加的，都是**波形/ADPCM 流**，不是芯片音乐：

| 格式 | 平台 | 现状 |
|---|---|---|
| **ADX（CRI）** | Dreamcast / PS2 / 街机 | ✅ 1.3 起可输出（ffmpeg `adpcm_adx`） |
| **Westwood AUD** | 命令与征服 / 红警 | ✅ 1.5 可输出（`adpcm_ima_ws`） |
| **APM** | Ubisoft Rayman 2 | ✅ 1.5 可输出（`adpcm_ima_apm`） |
| **ALP ADPCM** | Wii / PS2 部分游戏 | ✅ 1.5 可输出（`adpcm_ima_alp`，22.05k 单声道） |
| **SMAF（MMF）** | 功能机铃声 / 老游戏 | ✅ 1.5 可输出（`adpcm_yamaha`，8k 单声道） |
| **PS1 XA-ADPCM** | PS1 | ✅ 1.5 可输出（外部 `psxavenc`，Zlib，extras 包） |
| **PS2 VAG** | PS2 | ✅ 1.5 可输出（同上，单声道；立体声要双流） |
| **Wii/3DS BRSTM/BCSTM** | Wii / 3DS | ❌ 只有 vgmstream 等解码器，编码工具零散 |
| **Saturn** | 土星 | ❌ 没有通行的开源编码器/容器标准，基本只能 rip |

## 6. ToneBox 的红线

- 不把「芯片音乐」伪装成可输出格式——做不到就灰显/写清楚，这是产品底线
- 不内置 ROM、不内置原厂驱动、不碰版权素材
- 要接解码链（libgme / vgmstream）时，会把「渲染」这一步单独标出来，
  告诉用户听到的是模拟器渲染结果，不是原始录音
