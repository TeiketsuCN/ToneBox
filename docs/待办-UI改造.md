## 二、格式表拆分（防冲突的关键）

现在所有格式在一个数组里，两个人往里插必然冲突。改成：

```
crates/fc-core/src/format/
├── mod.rs        粘合 + 公共 API（谁都不许单方面改）
├── lossless.rs   ← 机器 A（我）负责
├── lossy.rs      ← 机器 B 负责
└── device.rs     ← ATRAC 等只读格式，双方都不动
```

```rust
pub fn all() -> impl Iterator<Item = &'static FormatSpec> {
    LOSSLESS.iter().chain(LOSSY).chain(DEVICE)
}
```

**契约变更**：静态量 `FORMATS` 改成函数 `all()`。
需要同步更新 `docs/契约.md`，并通知机器 B——它的 `format.rs` 权限范围要改成 `format/lossy.rs`。

## 三、侧栏要加的内容

### 无损组（我负责）

现有：FLAC / WAV / ALAC / AIFF

新增：

| 格式 | 扩展名 | 理由 |
|---|---|---|
| **WavPack** | `.wv` | 开源无损，压缩率略优于 FLAC |
| **TTA** | `.tta` | 结构极简，冷门但没坏处 |
| **CAF** | `.caf` | Apple 容器，可装 PCM/AAC |
| **W64** | `.w64` | Sony Wave64，处理 >4GB 录音必须用 |
| **裸 PCM** | `.pcm` `.raw` | 无文件头，喂硬件/老引擎用。小字要警告"播放器可能认不出" |

### 不做折叠，改成紧凑排布

用户否决了「更多」折叠。改为行高 24px、字号 11.5、`button_padding=(8,3)`，
让 13 个格式一屏铺完。侧栏仍可滚，但正常情况用不到。

### 明确不加的

| 名字 | 为什么不加 |
|---|---|
| **PCM** | 不是容器，是 WAV/AIFF 里面的数据本身。加了会和 WAV 重复 |
| **LPCM** | 同上，DVD/蓝光语境对无压缩音轨的叫法，落地就是 WAV/AIFF |
| WAV 的多个位深变体 | 会污染侧栏。位深改成全局设置 |

**替代方案**：在 WAV 的小字里写明「WAV 里装的就是 LPCM（线性 PCM）」，用户搜词能对上。

### WAV vs FLAC 的小字要讲透

用户最常问的不是「PCM 是什么」，而是「两个都是无损，选哪个」：

- FLAC 省一半空间，能存元数据，适合归档
- WAV 不省空间，任何软件都认，适合还要再编辑的素材

## 四、给机器 B 的提醒（有损组）

**能加的有损编码器其实很少：**

| 候选 | 能编码 | 建议 |
|---|---|---|
| MP2 | ✅ | 可加（广播/老 DVD） |
| WMA v2 | ✅ | 意义不大 |
| Speex | ✅ | 语音用，音乐不合适 |
| AMR-NB | ✅ | 手机录音时代遗产 |
| **AAC** | ✅ | ❌ 专利在保护期，不开放编码 |
| **AC-3 / E-AC-3** | ✅ | ❌ Dolby 专利，不开放编码 |

**B 的真正价值不在往侧栏塞格式，而在把「能解码但不宜编码」的那些写进百科。**

AAC / AC-3 / ATRAC9 这些：用户拖进来能听、能转出去，但侧栏不出现。
B 要做的是把这些格式的「是什么 / 什么来头 / 为什么不给编码」写清楚。

**侧栏控制在 9~11 个，百科做到 200 个。** 这个比例是对的。

### 设置项清单

**立即可用（现在硬编码的）：**
- 背景：壁纸模糊 / 纯色 / 关闭
- 模糊强度、暗化程度（`bg.rs` 里那两个常数）
- 输出目录：与源文件同目录 / 指定目录
- FLAC 压缩等级（0~12，默认 8）
- 转换后：保留源文件 / 删除源文件
- 并行转换数（现在是串行）

**新增：**
- **位深**：16 / 24 / 32-bit 浮点（全局，默认 24）
- 主题：跟随系统 / 深色 / 浅色（现在只有深色）
- 界面缩放

**持久化**：写到 `%APPDATA%\FormatConverter\config.json`，否则重开就还原。

**契约影响**：设置项要影响 `convert` 的参数（压缩等级、位深）。
不能让 GUI 拼 ffmpeg 参数——那会把格式知识漏到界面层。
方案：core 提供 `args_for(spec, &Options) -> Vec<String>`，GUI 只传 Options。

### 已踩的坑（写下来省得重踩）

- **`▾` `▲` `⏸` `⏹` 微软雅黑里没有**，会渲染成方块。所有图标改用 `painter` 画形状。
- **egui 的 `double_clicked()` 在 ScrollArea + Frame 里不触发**（跨帧 widget id 不稳定）。
  改成自己用时间差判定：同一行两次点击间隔 < 0.45s 即算双击。
- **按钮内边距会把行高撑大**：`min_size(24px)` 实际渲染 28px，要同时设 `button_padding`。
- **字体换宽之后**，队列行右侧预留宽度要从 168 加到 186，否则「待转换」被切。
- **`SetWindowSubclass` 在 windows-sys 里没有**（comctl32 那套没导出）。
  改用 `SetWindowLongPtrW(GWLP_WNDPROC)` 手动子类化，转发时用 `CallWindowProcW`。
- **`GetClientRect` 在 WindowsAndMessaging，`ScreenToClient` 在 Graphics::Gdi**，别搞混。
- **winresource 的 `compile()` 会失败也不该中断构建**：用 `let _ =` 吞掉错误，
  没图标总比编译不过强（机器 B 的环境未必有 windres）。
- **验证编码能力要用"随包的那份 ffmpeg"**：开发机装的是 gyan 全量版（有 `libspeex`），
  随包的是 LGPL 共享版（**没有** `libspeex`）。我按开发机验证开放了 Speex，
  用户装了包会转失败。凡是要暴露成输出格式，必须用 `D:\Apps\FormatConverter\ffmpeg\ffmpeg.exe`
  再验一遍。
- **PowerShell 5.1 的 `Get-Content` 会把 UTF-8 当 GBK 读**：用它读 `config.json`
  再 `ConvertTo-Json` 写回，中文会变成 `娴嬭瘯鑹轰汉` 这种乱码。改配置要用
  `[System.IO.File]::ReadAllText($p, [Text.Encoding]::UTF8)`。
- **整行点击会吃掉行内按钮**：`ui.interact(整行矩形)` 注册在按钮之后，
  交互层盖在上面，`×` / `···` 永远收不到点击（用户反馈两次）。
  解法：把按钮矩形并起来，整行点击的矩形从按钮左边界截断。
- **顶部 44px 是原生命中区**：`WM_NCHITTEST` 返回 `HTCAPTION` 之后，
  那块区域的点击被系统拿去当"拖标题栏"，**永远进不了 egui**。
  覆盖层的按钮如果放在 y<44 会完全点不动（Esc 能救，但按钮是死的）。
  解法：设置页内容整体下移 44px 避开。
- **无边框 + WS_THICKFRAME 最大化会大 8px**（窗口跑到 -8,-8）。
  `WM_GETMINMAXINFO` 里改 `ptMaxSize` 无效（被 DWM 覆盖），最后是在 UI 层补 8px 外边距。
- **给 `ConvertOptions` 加字段会让老 `config.json` 整个解析失败**：serde 遇到缺字段直接报错，
  `Settings::load()` 的 `unwrap_or_default()` 把用户所有设置静默重置（输出目录、元数据、
  背景全回到默认）。加字段必须配结构体级 `#[serde(default)]`，并写一个"老 JSON 还能读"
  的单测兜住。
- **体积估算不能只看 `size_ratio`**：AC-3 448k 实际就是 448 kbps，而 `0.1 × PCM 1411kps`
  只有 141 kbps，差三倍。有固定码率的格式要按「码率 × 时长」算，这样旋钮一调估计跟着变；
  无损和 Vorbis 这类没有固定码率的才退回 `size_ratio`。
- **Dolby 的码率和 48kHz 必须绑在一起**：AC-3 / E-AC-3 的合法码率档位是按 48kHz 定义的，
  `args_for` 里必须同时给 `-ar 48000`，否则 44.1kHz 输入时码率对不上（实测 192~640 全过，
  用随包那份 ffmpeg 验的）。
- **Opus 的输出流永远是 48kHz**：`libopus` 传 `-ar 192000` 也照样输出 48k（实测），
  所以**不能给它采样率旋钮**，否则界面上的选择和实际文件对不上——这是"按格式给档位"的最好例子。
- **采样率档位必须按编码器吸附**：全局设了 96k 再切到 MP3（只支持 32/44.1/48），
  不吸附就会把一个 `libmp3lame` 不接受的值丢过去，转换直接失败。`snap_rate` 就近取一档，
  界面高亮"实际会输出的值"而不是配置里的值。
- **升采样会凭空变大**：44.1k → 96k 的无损文件体积翻倍、信息一样多。必须在详情面板说出来
  （`quality_warnings` 第 5 条），否则用户会以为"采样率越高音质越好"。
- **atracdenc 的 `-e` 名字和文档对不上**：0.2.3 的 `-h` 写的是 `atrac3_lp`，
  实际只认 `atrac3_lp4`（LP4 66k）；man page 又写成 `atrac3_lp4`。写错时它只回一句
  "unrecognized encoding codec"，很难查。`-e` 的四个值：`atrac1` / `atrac3`（LP2 132k）/
  `atrac3_lp4`（LP4 66k）/ `atrac3plus`（352k）。
- **`--bitrate` 只对 RealMedia 容器生效**：对 `.oma` 是**静默忽略**（传 105 还是 132300），
  对 `.at3` 会生成 ffmpeg 解不开的帧。所以 ATRAC3 的档位只能用两个 `-e` 名字区分，
  不能靠码率参数；ATRAC3+ 目前只有 352k 一档。
- **atracdenc 是 32 位程序，非 ASCII 路径出过问题**：我们自己的样本就全是日文名。
  所以解码和编码都用 `%TEMP%` 下的 ASCII 临时名，最后再 `copy` 到目标路径（不用 rename，
  临时目录和目标可能不在一个盘）。
- **外部工具的查找顺序和 ffmpeg 故意相反**：atracdenc 先找程序目录、再找 PATH；
  ffmpeg 是先 PATH。原因是 atracdenc 由用户自己装，程序目录里那份最不容易版本打架。
- **GitHub 直连不稳**：`github.com/…/releases/download/…` 在国内经常 504，
  API 还会限流。`tools/fetch-atracdenc.ps1` 因此按"API asset → 钉住直链 → curl 重试"
  三层兜底，全失败就打印手动下载步骤，不假装成功。
- **控件不能按状态显示/隐藏**：AC-3 的「自动」等价于 48k，我一开始图省事——自动选中时
  把「自动」按钮藏掉、直接高亮 48k。结果用户点完「自动」，按钮自己消失、旁边 48k 亮起来，
  看起来像 bug（用户原话："选自动会变成 48k，然后自动按钮消失"）。
  规则：**同一排按钮的位置永远不动**，用高亮表示状态；语义不同就靠下面的小字解释。
- **标题栏按钮数量要和 `frame.rs` 的 `TITLE_BUTTONS` 对上**：`WM_NCHITTEST` 会把
  "右上角 N 个按钮"之外的上方区域返回 `HTCAPTION`。加了第 5 个按钮（设置）却忘了改这个数，
  新按钮正好落在 HTCAPTION 里——**看着能点，点了只是拖窗口**，一点反应都没有。
  改标题栏按钮时，`TITLE_BUTTONS` 和命中区的右边距（10px）必须一起改。
- **页面内容要能滚**：设置页在 100% 刚好放得下，切到 120% 就会把「关于/支持开发」切掉。
  `egui::ScrollArea` 包住正文（标题栏固定在外面），否则用户找不到下面的内容。
- **"可调字体"不能只改字体**：界面里到处是 `RichText::size(9.5)` 这种写死的字号，
  改 `text_styles` 根本不动。要缩放就用 `ctx.set_zoom_factor()`（整块 UI 一起缩放），
  并且把缩放同步给 `frame.rs` 的命中区计算（`set_ui_scale`），否则 120% 时按钮边缘会点不到。
- **整页覆盖层会把标题栏吃掉**：`Area` 里写 `ui.set_min_size(area.size())`，再加 `Frame`
  的 28/18 边距，内容就比区域大了；egui 会把 Area 往上顶到 y=0，`Order::Foreground` 的层
  于是盖住了标题栏——**设置页打开时，关闭 / 最小化 / 图钉 / 设置图标全都点不到**。
  查法：在标题栏里打一行 `ui.ctx().layer_id_at(pos2(1094.0, 22.0))`，正常应该是 titlebar 的
  Background 层，出问题时返回 Foreground。修法：`min_size` 扣掉 Frame 边距
  （`area.size() - vec2(56, 36)`），让 Area 的矩形正好等于那块区域。
- **`add_sized` 会把文本居中**：播放栏的标题用 `add_sized(vec2(w,14), Label...)` 时，
  标题跑到整条播放栏中间，看着像"没对齐"。要左对齐 + 截断就用
  `ui.add(Label::new(..).truncate())`，别用 `add_sized`。
- **横向布局里先放一个自适应宽度的 `ui.vertical`，后面的控件会被挤没**：播放栏里
  标题那行吃了整条宽度，右边的音量条只剩几个像素。修法：先扣掉右侧固定宽度
  （`content_w = 可用宽度 - 88`），用 `allocate_ui_with_layout` 把内容区锁宽，剩下的留给音量。
- **放大看封面要重新抽原图**：队列里的缩略图统一缩到 96×96，直接放大会明显糊。
  点开时后台跑一次 `extract_cover` + 缩放到 1000px，先显示缩略图、到了再替换。
- **音乐库扫描很慢**：每首歌要起两次 ffprobe（`probe` 拿时长/编码、`read_tags` 拿标签），
  68 首约 5 秒。所以扫描必须放后台线程，先回传总数（`LibMsg::Count`）进度才有分母，
  并且顺手 `request_repaint_after(150ms)`，否则界面不动。
- **列表行不要用 `add_sized` + Label 拼**：`add_sized` 会把文字居中，而且行高会被标签换行撑破。
  音乐库的行是用 painter 画的（`paint_clipped` + `layout` + `with_clip_rect`），行高固定 42。
- **输入框的样子不在 `TextEdit` 参数里**：底色是 `visuals.extreme_bg_color`、边框是
  `widgets.{inactive,hovered,active}.bg_stroke`、圆角是 `widgets.*.rounding`。
  只在单个控件上改没用，统一在 `App::new` 的 style 里改一次。
- **"添加"入口不能藏在页签里**：第一版把「添加文件夹」放在「库」页签内，用户直接找不到，
  以为没有这个功能。现在加音乐/加文件夹/重新扫描**常驻在音乐库页面顶部**，任何页签都在。
- **播放条贴底边很难看**：`TopBottomPanel` 直接 fill 会从窗口底边一直铺到边，
  改成"面板透明 + 内部一个圆角 Frame（带阴影）+ 底部 10px 外边距"，才有浮起来的感觉。
- **路径文字"歪"是因为 `paint_clipped` 从左上角开始画**：30px 行高里文字贴在顶部，
  看着像没对齐。用 `paint_clipped_v`（按 galley 高度取中线）才是垂直居中。
- **改名输入框要先清空缓冲、原名当 hint**：直接把原名填进 `TextEdit`，用户打字会接在后面
  （实测变成"配置 2车载配置"）。缓冲给空 + `hint_text(原名)`，空输入就保持原名。
- **egui 默认字体没有 "✎" "＋" 这些字形**，会画成豆腐块。用 `改`、`+` 这类一定有的字符。
- **封面别在扫描时全抽**：几千首会卡几分钟、纹理也吃显存。改成列表行进入视口才排队抽一张
  40×40，按路径缓存（`lib_covers`），重扫时清空。
- **改 PowerShell 脚本别把 BOM 弄丢**：`tools\install.ps1` 是 UTF-8 **with BOM**，
  `powershell.exe`（5.1）没有 BOM 就按 ANSI 读，中文注释会把字符串吃掉、直接语法错误
  （报"缺少右 }"，其实全是注释乱码）。用 edit 工具改完要补回 BOM：
  `[System.IO.File]::WriteAllText($p,$t,(New-Object System.Text.UTF8Encoding($true)))`。
  同理 `uninstall.ps1`、`fetch-*.ps1` 都是带 BOM 的。
- **`TopBottomPanel` 默认 resizable，会在边上画一条拖动分隔线**：用户说的"播放栏上面那条线"
  和"左下一行字上面的线"都是它，不是我们画的边框。统一加 `.resizable(false)` 就没了。
- **音质标识要预留宽度**：左边标题的 `set_max_width` 是减出来的，不把标识宽度算进去，
  徽章会直接盖在标题/副标题上。现在按"有标识再多留 58px"算。
- **NTFS 不区分大小写，改名的清理逻辑会删掉新快捷方式**：安装脚本先建 `ToneBox.lnk`，
  再"清理旧名 `tonebox.lnk`"，在 NTFS 上是同一个文件——结果装完桌面/开始菜单的快捷方式都没了，
  用户以为"应用打不开"（exe 本身没事）。清理列表里只能放**真正不同**的旧名（如中文名）。
- **懒加载封面/扫描结果要有重绘驱动**：后台线程回传以后，如果没有任何动画或输入，
  egui 不会重绘，界面就永远停在占位图。`lib_cover_pending` 非空时 `request_repaint_after(150ms)`。
- **音乐库别每次启动都扫**：结果写 `config.json` 的 `library_cache`（路径 + 标签 + 编码 + 码率 +
  采样率 + 位深 + 时长），启动铺出来；只有用户点「重新扫描」/加目录/加文件才重扫并回写。
- **"播放栏上面那条线"是 `show_separator_line`**：`TopBottomPanel` / `SidePanel` 默认
  `show_separator_line(true)`，即使 `resizable(false)` 也会在边上画一根细线。全部加
  `.show_separator_line(false)` 才干净。
- **播放栏右侧要留够宽度**：`vol_w` 是"音量 + 间隔 + 频谱按钮"的总宽，不够的话按钮会画在
  布局外面——看得见、点不到（这个坑找了半天）。
- **频谱别整首解码**：只解 8 秒（`decode_segment(..., None, Some(8.0))`）；显示前按峰值归一化，
  否则整条曲线贴着 0 dB；填充必须一段段画四边形，整条曲线不是凸的，`convex_polygon` 会画出斜线。
- **改基准缩小时窗口尺寸也要乘**：`BASE_ZOOM` 乘在 `set_zoom_factor` 上，同时 `with_inner_size`
  也要乘，否则 UI 点位不够、布局被挤。
- **别在界面里直接用 `egui::Slider`**：默认滑杆的配色/粗细和这套玻璃风完全不搭（用户原话"我吐了"）。
  压缩等级、Vorbis 质量、背景暗化都换成自绘的 `bar_slider`（细轨道 + 圆点 + 刻度 + 右侧数值）。
- **视频容器的 `format.bit_rate` 不是音频码率**：MKV 把画面和声音算在一起，直接拿来填
  `bitrate_kbps` 会出现"353kbps 的 AAC"。有音轨码率用音轨；没有又确实是视频就填 0
  （界面不显示码率、徽章只写"有损"），别硬凑。内嵌封面在 ffprobe 里也是一条 video 流，
  判断"是不是视频文件"要看 `disposition.attached_pic`。
- **标题栏里加的自绘按钮都要在 `frame.rs` 的命中区里放行**：右上角靠 `TITLE_BUTTONS`，
  左上角铃铛靠 `set_bell_left()`（逻辑坐标每帧同步）。不放行的话按钮看着能点、实际被当成拖窗口
  ——加设置按钮和加铃铛时各踩了一次。
- **通知面板要排除铃铛自己的点击**：点铃铛打开面板那一帧也会触发"点外面关闭"，
  不把铃铛矩形排除掉会开完立刻关。
- **采样率条右侧的数值要预留宽度**：`rate_slider` 按 `available_width() - 46` 算轨道，
  留不够的话「44.1k」会被窗口边缘切掉（一开始只留了 26）。「自动」状态下轨道上的点是暗色，
  手动选中才是强调色，别用同一个颜色。
- **别拿截止频率给 DSD 判档**：ffprobe 对 DSF 报的采样率是字节率（×8 才是 1-bit 率），
  DSD 也没有"码率档位"可推；`analyze()` 对 DSD 直接返回格式结论，别去解 90 秒 PCM 再套
  MP3/AAC 的阈值表。档位换算（`fc_core::dsd_tier`）是引擎逻辑，界面不要自己再写一份。
- **Hi-Res 徽章上的"小方块"/"四角"**：外发光是几个 `rect.expand()` 的圆角矩形，叠出来像方块；
  渐变色带用方角 `rect_filled` 画，四个角会从圆角描边外面露出直角；扫光带是斜的，
  扫到端点会从圆角外面透出白角。改法：去掉外发光；色带用 `rounded_band` 按 `corner_inset`
  裁进圆角；扫光用 `clipped_glint` 逐行和圆角求交（这样能从整枚徽章左端扫到右端，
  又不会冒出白角），再用三层不同宽度 + 递减透明度叠软边。
