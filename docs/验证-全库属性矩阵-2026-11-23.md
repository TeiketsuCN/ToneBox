## 失败清单（12 个，全部可解释）

| 源属性 | 目标 | 原因 |
|---|---|---|
| 96k/24bit | wma、wma_v1、wmv、swf、ogv | 这些容器/编码器只吃到 48k；参数层没兜住 96k |
| 96k/24bit | wsaud | 容器只认固定采样率档；96k 被写成 30464 Hz，时长 12s→38.11s（自检拦住了） |
| 96k/24bit | vadpcm | 只收 16-bit 输入；24-bit 源被拒 |
| 96k/24bit | musepack、qoa | 编码器不支持 96k |
| 48k 单声道 | swf | SWF 音频要求立体声；单声道源没自动补成 2.0 |
| 5.1 | wmv、swf | 视频容器还没按容器强制下混（音频目标已经做了） |

## 本轮据此修掉的问题

1. **5.1 源下混**（`crates/fc-core/src/format/mod.rs`）：
   音频目标里只吃单/双声道的编码器，在源 >2 声道时自动加 `-ac 2`。
   修之前 5.1 → wma / wma_v1 / lc3 / adx / voc 全部报 `cannot write header`；
   修之后全部正常出文件。
2. **外部编码器 5.1**（`crates/fc-core/src/external.rs`）：
   musepack / QOA / OptimFROG 解码成 WAV 时强制 2.0；
   之前 5.1 → 这三个格式直接失败。
3. **验证脚本过时的跳过**：`validate-real-music.ps1` 里把 12 个外部格式硬编码成
   `SKIP_EXTERNAL`，实际 CLI 早就派发了；已删除，现在真跑。
4. **工具回读**：新增 `tools/verify-output.ps1`，解决 ffmpeg 读不了 `.xa/.dsp/.idsp/.aifc/.ofr`
   导致的 5 个假失败。

## 仍然存在的限制（不是回归）

- 视频容器（wmv / swf / ogv）没有 96k / 5.1 的硬约束；音频目标已经有了，
  视频容器要照 mxf/psp/dv/gxf 的写法补 `-ac` / `-ar`。
- 采样率上限没有统一表：wma/wmv/ogv/swf ≤48k、wsaud 固定档、vadpcm 16-bit。
  目前靠转换后自检拦住（会报「时长不符」「编码失败」），不会静默产出坏文件。
- `--formats` 报 112 个目标，全库脚本只测 97 个音频目标；14 个需要视频源、1 个只做直通
  （IEC 61937）由单源脚本覆盖。
- 验证只覆盖「能产出 / 能解码 / 时长对得上」，不覆盖音质、画质、全部参数组合。
